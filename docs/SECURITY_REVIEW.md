### OWASP Top 10:2025（Web・API）

| 分類 | 確かめたこと | 結果 | 指摘 |
|---|---|---|---|
| A01 アクセス制御の不備 | 全ビューの `permission_classes`。メモ・日記・Daily は `owner` で絞り込み（他人の ID を指定すると 404）。タスクは自分＋共有の木だけ見えて、編集・削除・写真は持ち主だけ。Daily のチェックは自分の項目だけ。顧客ポータルは自分の予約・カードだけ（カードは Stripe 側で持ち主を確認）。Lab とポータルの権限は別。写真は署名付き URL で、`/media/` の直リンクは nginx で 404。ユーザー管理・権限管理の昇格 | 指摘あり | 1・7 |
| A02 セキュリティ設定のミス | 本番は `DEBUG=False`、`ALLOWED_HOSTS` は環境変数、`SECRET_KEY` は必須、Admin は既定で無効。HTTP→HTTPS のリダイレクトあり。HSTS・CSP・`X-Frame-Options` などのヘッダー、`X-Forwarded-Host` の扱い、CORS（許可するオリジンを列挙。`*` は使っていない） | 指摘あり | 3・12 |
| A03 ソフトウェアのサプライチェーンの不備 | `pip-audit`（脆弱性なし）、`npm audit`（High 7 件）、`flutter pub outdated`、Docker のベースイメージの版 | 指摘あり | 4・5・17 |
| A04 暗号の不備 | 通信は Let's Encrypt の TLS。パスワードは Django 既定の PBKDF2。JWT と写真の署名は `SECRET_KEY`（環境変数）で、写真は用途ごとの salt 付き・1時間で失効。招待・再設定のトークンは Django の仕組みで、用途ごとに別の生成器 | 問題なし | — |
| A05 インジェクション | SQL は ORM だけ（`raw`・`extra` なし）。Vue に `v-html` はなく、テンプレートの文字列は自動でエスケープされる。メールのヘッダーは Django が改行を拒否。`:href` にサイトコンテンツの URL をそのまま入れている所 | 指摘あり | 6 |
| A06 安全でない設計 | お問い合わせの回数制限（送信者のアドレスへ自動返信する）。ポータルの空き枠の期間の上限。写真のサイズ（20MB・nginx も 20MB）と画素数 | 指摘あり | 2・14 |
| A07 認証の失敗 | ログインは IP ごと 10回/分＋ユーザー名ごと 10 回失敗で 15 分ロック（2026-10-30）。アクセストークン 15 分・refresh 7 日・ローテーションで古い refresh を失効・ログアウトとパスワード変更で失効（2026-10-30）。パスワード再設定は登録の有無で応答が同じ・宛先ごと 5 分に 1 通・1時間で失効・1回限り。招待リンク・パスワードの強さ・トークンの保存場所 | 指摘あり | 8・9・10・11 |
| A08 ソフトウェアとデータの整合性の不備 | Stripe の Webhook はない（カード登録は SetupIntent をフロントで確定するだけ）。信頼できないデータの逆シリアル化（pickle 等）なし。CI はなく、デプロイは手元から rsync | 該当なし（Webhook・CI がない） | — |
| A09 セキュリティのログと通知の不備 | ログイン失敗・ロック・権限エラーの記録 | 指摘あり | 13 |
| A10 例外的な状態の扱いの誤り | 本番は `DEBUG=False` で、例外の中身は画面に出ない。メール送信の失敗はログに残して続行。入力の形が違うと 500 になる所、Stripe の例外の文字列を返している所 | 指摘あり | 15・16 |
